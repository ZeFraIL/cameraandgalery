## 🎯 Цель проекта
•	**Какую задачу решает приложение:** Позволяет пользователю делать фотографии и записывать видео, автоматически сохраняя метаданные файлов (имя, дата, время, путь) в локальную базу данных для последующего просмотра.
•	**Почему эта задача важна:** Упрощает организацию медиафайлов и предоставляет быстрый доступ к информации о созданных файлах в одном месте.
•	**Целевая аудитория:** Пользователи, которым необходимо вести учет созданного медиаконтента.
________________________________________
## 📌 Требования к приложению
### Функциональные требования
•	Создание фото через системную камеру.
•	Запись видео через системную камеру.
•	Сохранение информации о файле (имя, дата, время, URI) в SQLite.
•	Просмотр списка всех сохраненных записей.
•	Просмотр деталей файла (превью фото или воспроизведение видео с элементами управления) во всплывающем диалоге.
•	Открытие системной галереи.

### Нефункциональные требования
•	**Производительность:** Быстрая загрузка списка файлов из БД в фоновом потоке с использованием RecyclerView.
•	**Удобство использования:** Простой интерфейс с четырьмя основными кнопками на главном экране и адаптацией под системные отступы (Edge-to-Edge).
•	**Надёжность:** Современная обработка разрешений (ActivityResultContracts.RequestPermission) и безопасность работы с файлами через FileProvider.

## 🧩 Подробное описание классов
### 📌 Класс: Start
**Роль:** Заставочный экран (Splash Screen).
**Ответственность:** Отображение заставки с таймером (2 секунды), безопасная отмена таймера в `onDestroy()`, запуск `MainActivity` и завершение работы через `finish()`.

### 📌 Класс: MainActivity
**Роль:** Главный экран приложения.
**Ответственность:** Управление жизненным циклом, обработка нажатий кнопок, запуск Intents для камеры/видео, безопасный запрос разрешений через `ActivityResultLauncher`, асинхронная запись в БД.
**Основные методы:**
- `onCreate()` — инициализация UI, лаунчеров и Edge-to-Edge.
- `checkCameraPermissionAndExecute()` — проверка и запрос разрешения на камеру.
- `dispatchTakePictureIntent()` — запуск камеры для фото.
- `dispatchTakeVideoIntent()` — запуск камеры для видео.
- `openGallery()` — корректное открытие системной галереи.
- `saveFileInfoToDatabase()` — асинхронная запись данных в БД в фоновом потоке.

### 📌 Класс: DatabaseHelper
**Роль:** Слой данных.
**Почему используется:** Для работы с локальной базой данных SQLite, хранения структуры таблиц и выполнения запросов.

### 📌 Класс: FileInfo
**Роль:** Модель данных.
**Описание:** Содержит поля `name`, `date`, `time`, `uri`, `type` для представления информации о медиафайле.

### 📌 Класс: ViewInfoAboutMyFiles
**Роль:** Экран просмотра списка.
**Ответственность:** Асинхронная загрузка данных из БД в фоновом потоке, отображение их в RecyclerView через адаптер с предпросмотром видео/фото через Glide, показ диалога с интерактивным плеером.
________________________________________
## 🔄 Диаграмма работы приложения
1. При старте запускается `Start` с таймером 2 сек.
2. Открывается `MainActivity`. Пользователь нажимает "Make a photo" или "Make a video".
3. Проверяется/запрашивается разрешение на камеру. Открывается системная камера.
4. После съемки данные (путь к файлу и время) сохраняются в SQLite в фоновом потоке.
5. Пользователь переходит в "View info", где из фонового потока загружается список файлов.
6. В списке с помощью Glide отображаются кадрированные превью изображений и видео.
7. При нажатии на элемент списка открывается диалог с деталями и видеоплеером (с `MediaController`).

## 🎨 UI/UX анализ
•	**Почему интерфейс сделан именно так:** Использована плиточная структура кнопок для быстрого доступа к основным функциям и Edge-to-Edge адаптация.
•	**Какие принципы использованы:**
–	**Простота:** Минимальное количество действий для достижения цели.
–	**Логичность:** Группировка действий по смыслу.
•	**Что можно улучшить:** Добавить поддержку темной темы и возможность удаления записей.
________________________________________
## ⚙️ Работа с потоками
•	**Используются ли:**
- Да. Чтение и запись в базу данных SQLite выполняются асинхронно в фоновом потоке с использованием `ExecutorService`.
•	**Как предотвращаются зависания (ANR):** 
- Операции ввода-вывода (I/O) SQLite вынесены из основного потока (UI Thread).
- Использование эффективных методов Glide для загрузки и декодирования изображений и превью видеофайлов.
________________________________________
## 💾 Работа с данными
•	**Где хранятся данные:** Локальная БД SQLite (all_info.db) и приватный внешний каталог приложения `getExternalFilesDir()` (для медиафайлов).
•	**Почему выбран этот способ:** Обеспечивает автономность, соблюдение прав доступа Android и быструю выборку данных без интернета.
________________________________________
## 🌐 Работа с сетью
